# Skill: web-dev-flow (一站式网站开发与部署)

## 技能描述

让任何人（包括零代码基础用户）在 AI 辅助下，从 0 到 1 完成一个网站的开发、测试与部署上线。覆盖需求构思、项目搭建、功能开发、UI/UX 设计、测试优化、部署上线六大阶段。每个阶段提供标准操作步骤、可复制的 AI 提示词模板、避坑指南和验收标准。

**参考案例**：Dreamcore 数字艺术社交平台（20+功能模块，220件作品，Netlify 免费部署）

---

## 触发条件

当用户提出以下意图时激活此技能：
- "帮我做一个网站"
- "从0搭建一个网页"
- "我想做一个XX平台"
- "开发一个落地页/个人博客/作品集/电商站"
- "帮我部署上线"
- 任何涉及"从零开始建站"的需求

---

## 核心原则（贯穿所有阶段）

> **1. 先查后做** — 任何不熟悉的任务，先用 WebSearch 确认最新信息，不要凭记忆猜测
>
> **2. 分阶段交付** — 每完成一个阶段就让用户验收确认，不要等全部做完再展示
>
> **3. 功能检测优于假设** — 不要假设设备/浏览器/网络能力，用代码实际检测
>
> **4. 精简输出** — 只说结论和关键信息，不要输出不必要的代码和解释
>
> **5. 先确认环境再行动** — 部署前先确认用户的网络环境（国内/海外），选择对应可用的平台

## 阶段 1：需求与规划

### 目标
用 3-5 轮对话明确项目定位、核心功能和技术方案，形成一份可执行的需求清单。

### 标准操作步骤

- [ ] 1.1 收集用户基本信息：项目名称、定位、目标用户
- [ ] 1.2 梳理核心功能清单（MVP，不超过10个功能）
- [ ] 1.3 确认技术栈（前端框架、UI库、动画库、部署平台）
- [ ] 1.4 确认设计风格（配色、字体、参考网站）
- [ ] 1.5 生成需求文档并让用户确认

### 常见坑与避坑指南

| 坑 | 避坑方法 |
|:---|:---|
| 功能太多导致开发周期无限延长 | 严格控制 MVP 在 5-8 个核心功能，其他列为 P2 后续迭代 |
| 技术栈选择凭直觉 | 先用 WebSearch 搜索"XX框架 2026 对比"，确认最新状态 |
| 需求不明确就开始写代码 | 必须让用户确认需求文档后再进入下一阶段 |
| 忽略目标用户的网络环境 | 如果用户在国内，优先选择国内可访问的方案 |

### 验收标准
- [ ] 用户确认了需求文档
- [ ] 功能清单不超过 10 个，有明确的优先级
- [ ] 技术栈已确定，用户理解每个选择的理由
- [ ] 设计风格已确认（配色、字体、参考案例）

## 阶段 2：项目初始化

### 目标
搭建可运行的项目骨架，包含目录结构、构建配置、开发服务器，做到 `npm run dev` 一键启动。

### 标准操作步骤

- [ ] 2.1 初始化项目：`npm create vite@latest . -- --template vanilla/vue/react`
- [ ] 2.2 创建目录结构：css/、js/、images/、public/
- [ ] 2.3 配置 vite.config.js（base路径、构建选项、代理）
- [ ] 2.4 创建 index.html 主页面骨架
- [ ] 2.5 创建 CSS 变量系统（亮色/暗色双主题）
- [ ] 2.6 创建 main.js 入口文件
- [ ] 2.7 验证 `npm run dev` 和 `npm run build` 正常工作

#### 项目初始化模板

1. 项目名称：{名称}
2. 模板：vanilla（纯JS）/ vue / react

   - css/          → 样式文件

#### CSS 变量系统模板
```

   - --scrollbar-track（滚动条轨道，亮暗色不同）

### 常见坑与避坑指南

| 坑 | 避坑方法 |
|:---|:---|
| base 路径配置错误导致部署后资源404 | 根路径部署用 `base: '/'`，子路径用 `base: '/子路径/'` |
| CSS变量命名不统一 | 开始就定义完整的变量命名规范，后续严格遵守 |
| 静态文件放在根目录而非 public/ | privacy.html、robots.txt 等必须放在 public/ 目录 |
| vite.config.js plugins 数组为空 | 安装了插件必须在配置中注册，否则不生效 |

### 验收标准
- [ ] `npm run dev` 能正常启动开发服务器
- [ ] `npm run build` 能正常生成 dist/ 目录
- [ ] 目录结构清晰，命名规范统一
- [ ] CSS 变量系统完整，亮色/暗色主题都可用
- [ ] 浏览器打开 localhost 无控制台错误

## 阶段 3：核心开发

### 目标
按功能清单逐模块开发，每个模块完成后立即验证，确保功能可用。

### 标准操作步骤

- [ ] 3.1 按优先级排序功能清单（P0 → P1 → P2）
- [ ] 3.2 每个功能模块按以下流程开发：
  - 写 HTML 结构
  - 写 CSS 样式
  - 写 JS 交互逻辑
  - 浏览器验证功能正常
- [ ] 3.3 每完成一个模块，控制台检查无错误
- [ ] 3.4 数据管理：MVP用 localStorage，复杂项目用 Firebase/Supabase
- [ ] 3.5 代码分割：按功能模块拆分 JS 文件，Vite 自动 code splitting

### AI 提示词模板

#### 功能模块开发模板
```
开发 {模块名称} 功能模块：

功能描述：{一句话描述}
涉及文件：{HTML/CSS/JS文件名}
核心交互：{用户操作 → 系统响应}

技术要求：
1. 使用 CSS 变量系统，禁止硬编码颜色
2. 使用语义化 HTML 标签（article/section/nav/dialog）
3. 添加 aria 标签提升可访问性
4. 使用 addEventListener 绑定事件，不要用 onclick 属性
5. 所有 DOM 操作前检查元素是否存在
6. 弹窗的 open/close 必须对称（close 逆转 open 的所有副作用）

完成后在浏览器中验证：打开页面 → 执行操作 → 确认功能正常 → 检查控制台无错误。
```

#### CSS 主题适配检查模板
```
检查以下 CSS 代码是否正确支持亮色/暗色双主题：

检查项：
1. 所有颜色值是否使用 CSS 变量？（禁止硬编码 rgba/hex/rgb）
2. ::selection 颜色是否使用 var(--text-primary)？
3. ::-webkit-scrollbar-track 是否使用变量？
4. 弹窗/模态框背景是否使用 --modal-bg 变量？
5. 深色遮罩（如图片上的文字遮罩）除外 — 这些可以硬编码深色

输出：列出所有违规的硬编码颜色值，给出修复建议。
```

#### 弹窗组件开发模板
```
开发一个弹窗/模态框组件，要求：

HTML结构：
- 使用 <dialog> 标签或 aria-modal="true"
- 包含标题、内容区、操作按钮

CSS要求：
- 背景使用 var(--modal-bg)
- 使用 backdrop-filter: blur() 实现毛玻璃效果
- z-index 层级管理（弹窗 > 导航 > 内容）

JS要求：
- open(): 显示弹窗 + 锁定页面滚动 + 绑定焦点陷阱 + ESC关闭
- close(): 隐藏弹窗 + 解锁滚动 + 移除焦点陷阱 + 清空输入框 + 重置所有状态
- open/close 必须完全对称！close 必须逆转 open 的所有副作用

⚠️ 避坑：close 时必须清空 input.value、重置业务状态变量、恢复初始UI
```

### 常见坑与避坑指南

| 坑 | 避坑方法 |
|:---|:---|
| 动态 import 的模块用全局变量引用 | 通过存储的引用访问：`const THREE = this.THREE` |
| const 变量暂时性死区 (TDZ) | 函数内引用外部变量时确保声明在前，或用 `getElementById` |
| GSAP 对空选择器报警告 | 使用前检查 `querySelectorAll().length > 0` |
| 表单原生验证阻止JS逻辑 | `<form>` 添加 `novalidate` 属性 |
| 弹窗关闭后状态残留 | close 中必须清空输入框、重置状态、恢复初始UI |
| 硬编码颜色值导致主题切换失效 | 所有颜色必须通过 CSS 变量引用 |

### 验收标准
- [ ] 所有 P0 功能正常可用
- [ ] 亮色/暗色主题切换无视觉异常
- [ ] 控制台无 JavaScript 错误
- [ ] 弹窗打开/关闭状态管理正确
- [ ] 表单验证有明确的错误提示

## 阶段 4：UI/UX 设计

### 目标
确保视觉设计一致、响应式适配、交互体验流畅。

### 标准操作步骤

- [ ] 4.1 建立设计规范：颜色、字体、间距、圆角、阴影
- [ ] 4.2 响应式适配：桌面端(1440px)、平板(768px)、手机(375px)
- [ ] 4.3 交互体验：hover效果、过渡动画、加载状态
- [ ] 4.4 无障碍：键盘导航、aria标签、对比度
- [ ] 4.5 双主题检查：逐页面检查亮色/暗色模式

### AI 提示词模板

#### 响应式适配模板
```
为以下页面添加响应式适配：

桌面端(>1200px)：{布局描述}
平板端(768-1200px)：{布局描述}
手机端(<768px)：{布局描述}

要求：
1. 使用 CSS Grid/Flexbox 实现布局
2. 移动端导航使用汉堡菜单
3. 卡片/列表在小屏幕下改为单列
4. 图片使用 max-width: 100% 防止溢出
5. 触摸目标最小 44x44px
6. 使用 @media 查询，断点：768px、1024px、1200px
```

#### 交互体验优化模板
```
检查并优化以下交互体验：

1. 所有可点击元素是否有 hover/active 状态？
2. 页面切换是否有过渡动画？（推荐 0.3s ease）
3. 加载状态是否有骨架屏或loading指示器？
4. 表单提交是否有 loading 状态防止重复点击？
5. 滚动动画是否流畅？（使用 transform 而非 top/left）
6. 自定义光标是否在触屏设备上禁用？

修复所有发现的问题。
```

### 常见坑与避坑指南

| 坑 | 避坑方法 |
|:---|:---|
| 亮色模式下白色文字不可读 | `::selection { color: var(--text-primary) }` |
| 滚动条在亮色模式不可见 | 滚动条轨道颜色需要亮暗色两套变量 |
| navbar 滚动时 padding 变化导致 CLS | 固定 navbar 的 padding，不要在滚动时改变 |
| 触屏设备自定义光标不显示 | 用 JS `pointermove` 事件检测，不要用 CSS 媒体查询 |

### 验收标准
- [ ] 三种视口尺寸下布局正常
- [ ] 亮色/暗色主题下所有页面无视觉异常
- [ ] 所有可交互元素有 hover/active 状态
- [ ] 关键对比度符合 WCAG AA 标准

3. 部署 dist/ 到 {平台}
4. 验证公网链接可访问
5. 测试关键功能

注意事项：
- 如果部署到子路径（如 /dreamcore/），需要配置 vite.config.js 的 base 选项
- Netlify 根路径部署，base 设为 '/'
- 所有资源路径必须与 base 配置一致
```

### 常见坑与避坑指南

| 坑 | 避坑方法 |
|:---|:---|
| 国际平台在国内被墙 | **部署前先搜索确认国内访问情况**，优先 Netlify |
| Gitee Pages 已停服 | 搜索确认平台最新状态，不要假设 |
| 子路径部署资源404 | 配置 Vite 的 `base` 选项，与部署路径一致 |
| PowerShell 中 git push URL 被拆断 | 用双引号包裹整个 URL |
| Git SSL 证书错误 | `git config http.sslBackend schannel` |
| 静态文件未复制到 dist/ | privacy.html、robots.txt 等放在 public/ 目录 |

## 附录 D：10 条核心经验

| # | 经验 | 来源 |
|:---|:---|:---|
| 1 | **先查后做** — 不熟悉的任务先搜索确认 | 部署踩坑4个平台 |
